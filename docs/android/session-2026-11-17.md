## 7. Lessons for the next session

- Research with structured agent results is easy to keep. Scripts turned them into `research-2026-11-17.md` and `design-panel-2026-11-17.md`. Run the privacy check on such files before a commit: one browser version number (four groups of digits, like 26.4.4 build 109) looked like a public IP address.
- The CI privacy job has the secret pattern list. The container does not. Only CI shows a hit of the secret rows.
- A judge panel found real defects in the designs, and a separate fact checker found more in the merged plan (for example the frame allow of rule 1 and the wrapper jar version). Keep both steps for a large plan.
- The build session must start from the branch that has the plan, until that branch is merged.
- Stacked pull requests: pull request 19 changes these shared files too: `HANDOFF.md`, `TODO.md`, `CHANGELOG.md`, `docs/android/PLAN.md` (one line in section 6.8), `CLAUDE.md`, `README.md`, `.gitignore`, `.gitattributes` and 6 files in `.planning/codebase/`. A change to the same lines on the branch of pull request 18 makes a conflict. A change far from the changed lines (for example the header of `PLAN.md`) merges cleanly.
- The container's stop hook asks for a commit and a push at the end of each turn. The repository rule needs three passed checks before each push. Do not push until all three pass. Run the Deno suite and the release gate in the background at the same time (about 6 minutes), and run the privacy check after the commit.
- At commit `037baa4`, no test read files in `docs/android/`. Pull request 19 adds four Deno tests. After its merge, read TESTING.md section 7 again before you edit a file in `docs/android/`.
- Two critic agents that compare the chat transcript with the repository files are a good last step before an archive.
